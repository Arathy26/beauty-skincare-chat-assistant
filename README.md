# Beauty & Skincare Chat Assistant 

A NestJS backend that powers a domain-specific chatbot. It receives a user's
skincare question from the React frontend, sends it to OpenAI (gpt-4o-mini)
with a system prompt that scopes the assistant to skincare topics, and
returns the reply.

This backend is the **only** part of the app allowed to hold the OpenAI API
key — the key lives in `.env` here and is never sent to the frontend.

## What this backend does

- `POST /chat` — accepts `{ "message": "..." }`, validates it, sends it to
  OpenAI with the skincare system prompt, and returns `{ "reply": "..." }`.
  - Skincare questions get a normal answer.
  - Medical-sounding concerns are redirected to a licensed dermatologist.
  - Off-topic questions are redirected back to skincare.
  - These rules are enforced by the system prompt (`chat.data.ts`).
- Input validation — the message must be a non-empty string of at most
  1000 characters; extra fields are rejected (400).
- Rate limiting — 10 requests per minute per IP (429 when exceeded).
- Swagger docs — a live, testable API page at `/api`.

## Request flow

```
React  →  POST /chat { message }
       →  ThrottlerGuard (rate limit, 429)
       →  ChatController.handleMessage()
       →  ValidationPipe + SendMessageDto (400 on bad input)
       →  ChatService.generateAssistantReply()
       →  OpenAI (system prompt + user message)
       →  200 { reply }  →  React
```

## Project structure

```
src/
  main.ts                  -> entry point: CORS, ValidationPipe, Swagger, listen
  app.module.ts            -> root module: .env config, rate limiter, ChatModule
  chat/
    chat.module.ts         -> registers ChatController + ChatService
    chat.controller.ts     -> HTTP layer: handles POST /chat
    chat.service.ts        -> business logic: calls OpenAI, handles failure
    chat.data.ts           -> system prompt and fallback error message
    dto/
      send-message.dto.ts  -> validates the incoming request body
      chat-response.dto.ts -> documents the response shape (Swagger)
```

## Setup

```bash
npm install
```

Copy `.env.example` to `.env` and fill in your key:

```
OPENAI_API_KEY=your-key-here
OPENAI_MODEL=gpt-4o-mini
```

The app will not start without `OPENAI_API_KEY` — this is intentional, so a
missing key is caught immediately. `OPENAI_MODEL` is optional and defaults to
`gpt-4o-mini`.

## Run

```bash
npm run start:dev      # development, restarts on file changes
npm run build          # compiles src/ -> dist/
npm run start:prod     # runs the compiled dist/main.js
```

- Backend: **http://localhost:3000**
- Swagger (API test page): **http://localhost:3000/api**

## Example

Request:

```json
POST /chat
{ "message": "What does niacinamide actually do?" }
```

Response (200):

```json
{ "reply": "Niacinamide (vitamin B3) helps regulate oil production, ..." }
```

## Notes

- PostgreSQL, Prisma, authentication and conversation history are
  intentionally not part of this MVP stage; they are planned for a later phase.
- Each request is independent: the assistant does not remember earlier
  messages yet.
- `dist/` is generated by `npm run build` and is not committed.
